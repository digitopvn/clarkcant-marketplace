# AGENTS.md

Guidance for coding agents and contributors working in this repository. Humans start at the [README](README.md).

## What this is

A pnpm monorepo for the ClarkCant package marketplace on Cloudflare Workers (Astro SSR + Hono API + D1/R2/Queues/
Workflows). The marketplace discovers and curates packages; npm distributes them; ClarkCant installs and runs them.
Read [docs/architecture.md](docs/architecture.md) before changing structure.

## Commands

```sh
pnpm install
pnpm db:migrate:local      # once, and after pulling new migrations
pnpm dev                   # http://localhost:4321
pnpm verify                # lint + typecheck + unit/integration tests (must pass before you finish)
pnpm build                 # web Worker build + jobs Worker dry-run bundle
pnpm migrations:check      # schema and migrations in sync
pnpm test:e2e              # Playwright; BASE_URL=... to target a running server
```

Run the narrowest test first (`pnpm exec vitest run --project <name>`), then `pnpm verify`.

## Rules that are easy to break

- **Layers**: pages, API routes, MCP tools and job handlers call `packages/marketplace` services. No SQL outside
  services and `packages/db`. Shared shapes live in `packages/contracts` (Zod only).
- **Tests use a real D1** in workerd with every migration applied. Do not mock the database.
- **Migrations** are generated from the Drizzle schema (`pnpm db:generate`), additive, and never edited after they
  are applied. `packages/db/src/schema/auth.ts` is generated by the Better Auth CLI.
- **`package_versions` rows are immutable.**
- **CSP**: pages run under a hashed Content Security Policy in production builds. No inline event handlers, no
  third-party scripts. Inline scripts and styles must be fixed strings hashed in `apps/web/astro.config.ts`
  (runtime hash inserts do not reach the policy). `astro dev` does not enforce CSP, so check with a production build
  (`E2E_BUILT=1`, see the README).
- **Public pages ship little JavaScript**: prefer an Astro component with a small `<script>` to a React island; the
  e2e budget is 120 KB per public page.
- **Trust wording**: `listed` means "passed automated checks, not human-reviewed"; `featured` is the curated signal;
  npm provenance is "recorded, not verified". Never describe a package as reviewed, verified or safe beyond that
  ([security boundaries](docs/security-boundaries.md#curation-and-trust)).
- **Page blocks, API routes, indexing checks** each have one extension path:
  [blocks](docs/extending-blocks.md), [API](docs/extending-api.md), [indexers](docs/extending-indexers.md).
  An API change regenerates the SDK types (`pnpm --filter @marketplace/sdk openapi:generate`).
- **Secrets** never go in files. Local overrides live in `apps/web/.dev.vars` (git-ignored); deployed secrets use
  `wrangler secret put`. Never run `--remote` commands or deploy from a workstation; CI deploys
  ([deployment](docs/deployment.md)).
- **No fake data**: seed through the real services (`Create default pages`, `pnpm index:local` with a real tarball).

## UI and discovery surfaces

- Visual, motion and voice rules for public pages are in [DESIGN.md](DESIGN.md); the review checklist (three
  viewports, 320 px reflow, 24 px targets, keyboard, reduced motion, Markdown twins, JSON-LD) is in
  [REVIEW.md](REVIEW.md). Attach screenshots at 1440, 768 and 375 px to any PR that changes public UI.
- Builder-page HTML is rendered inside the engine's `.pe-page` column; do not wrap it in another `container-page`.
- A new indexable page needs a Markdown twin with absolute links, a `rel="alternate"` link and, when it is a starting
  point, an entry in `/llms.txt` (`apps/web/src/server/site-index.ts`).

## Agent-facing surfaces of the product

If you are an agent using the marketplace rather than changing it: `/llms.txt`, Markdown twins (`<page>.md`),
`/openapi.json`, the MCP server at `/mcp` ([docs/mcp.md](docs/mcp.md)), and the `clark-market` CLI
([docs/cli.md](docs/cli.md)).
